<objective>
Make the roster data-driven and make a wrong roster a boot-time crash instead of a runtime 404. Load the six model IDs, their labs, and their per-model reasoning mode from `models.yaml`; cross-check every one against OpenRouter's live `/models` catalog before the dispatcher is allowed to start; and package the whole thing for Docker Compose.

This is the plan that structurally prevents the project's single largest known config risk — a model ID that does not exist, or a roster that has quietly collapsed to three labs.

Purpose: no model ID is ever hardcoded in Python, and the bot cannot serve a single question against an invalid roster.
Output: `models.yaml`, typed settings, a live boot validator with a `--validate-only` entrypoint, and a Docker Compose deployment.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host environment → bot process | `OPENROUTER_API_KEY` and `TELEGRAM_BOT_TOKEN` enter here |
| Bot process → openrouter.ai | Outbound HTTPS at boot; response is attacker-influenceable only if DNS/TLS is compromised |
| Repository → container image | Anything not excluded by `.dockerignore` ships to the VPS |
| Process → docker json-file log driver | Everything on stdout persists on disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information disclosure | `Settings` in a stack trace or log line | mitigate | `telegram_bot_token` and `openrouter_api_key` typed as `pydantic.SecretStr`; acceptance criterion asserts the raw value is absent from `repr(Settings())`. |
| T-02-02 | Information disclosure | `.env` baked into the Docker image | mitigate | `.env` listed in `.dockerignore`; acceptance criterion asserts `ls /app` in the built image does not show it. Secrets arrive at runtime via `env_file`. |
| T-02-03 | Tampering | `yaml.load` on `models.yaml` enabling arbitrary object construction | mitigate | `yaml.safe_load` only; acceptance criterion greps for the absence of `yaml.load(`. |
| T-02-04 | Elevation of privilege | Container running as root on the VPS | mitigate | Dockerfile creates uid 10001 and sets `USER bot` before `CMD`; acceptance criterion asserts `id -u` is 10001. |
| T-02-05 | Spoofing | A hostile response from the `/models` endpoint marking a bad model as valid | accept | The endpoint is reached over HTTPS with certificate validation on by default in httpx; a compromised OpenRouter is out of this project's threat model since every inference call already trusts it. |
| T-02-06 | Denial of service | `/models` hanging at boot and wedging the container | mitigate | The catalog GET carries an explicit 15-second timeout and any `httpx.HTTPError` becomes a `BootValidationError` and a non-zero exit, which `restart: unless-stopped` then retries. |
| T-02-07 | Information disclosure | `Authorization` header sent to the public catalog endpoint and captured in a proxy log | mitigate | No `Authorization` header is sent to `/models`; acceptance criterion greps for its absence in `boot.py`. |
</threat_model>
