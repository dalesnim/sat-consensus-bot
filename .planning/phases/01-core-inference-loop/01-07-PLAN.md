<objective>
Replace the project's single biggest MEDIUM-confidence assumption with a measurement. Research put the worked example at roughly 27 seconds against a 30-second budget, interpolated from third-party general benchmarks onto an *estimated* completion-token count — never measured against this prompt, this image shape, or these six models.

This plan ships a standalone spike script that fires all six models once with the real `SYSTEM_PROMPT` and a real SAT question photo, logs actual wall-clock time, actual `usage.completion_tokens`, and actual `usage.cost` per model, and produces the number that decides whether `max_tokens` stays at 2000. The script is written and committed now; it runs the moment an `OPENROUTER_API_KEY` exists.

Purpose: stop trusting the latency budget and start knowing it.
Output: `scripts/latency_spike.py`, a README, and a recorded `SPIKE-RESULTS.md` with the `max_tokens` decision.
</objective>
