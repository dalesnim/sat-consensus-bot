<objective>
Build the pre-flight gate that stands between a user's photo and roughly seventeen cents of inference spend. Decide which Telegram file to download, refuse oversized payloads before decoding them, and grade the image on resolution and blur so an unreadable photo is turned away rather than silently OCR-hallucinated by six models at once.

Everything here is a pure function over bytes. No aiogram objects, no `Settings` import, no network — the thresholds arrive as arguments so plan 06 can wire them from the environment and this module stays testable in isolation.

Purpose: attack the project's dominant named failure mode (bad OCR from a compressed photo) upstream of the money.
Output: `src/bot/images/extract.py` with a three-level quality verdict and a base64 data-URL encoder.
</objective>

    Extend `src/bot/images/extract.py` with `QualityGrade(StrEnum)` — members `ok`, `warn`,
    `reject` — and `QualityReport(BaseModel)` with `grade: QualityGrade`, `width: int`,
    `height: int`, `blur_variance: float`, `reason: str | None`.

    Write
    `grade_image(data: bytes, *, min_dimension: int, blur_warn: float, blur_reject: float) -> QualityReport`.
    Open with Pillow, convert to `"L"`, record `width` and `height`, then compute Laplacian
    variance without numpy or opencv: apply `ImageFilter.Kernel(size=(3, 3), kernel=(0, 1, 0, 1, -4, 1, 0, 1, 0), scale=1, offset=128)`
    and take `ImageStat.Stat(filtered).stddev[0] ** 2` as `blur_variance`.

    Grading order:
    1. If `min(width, height) < min_dimension // 2` -> `reject`, reason names the resolution and the floor.
    2. If `blur_variance < blur_reject` -> `reject`, reason names the blur measurement.
    3. If `min(width, height) < min_dimension` or `blur_variance < blur_warn` -> `warn`, reason
       names which check tripped.
    4. Otherwise -> `ok`, `reason is None`.
    The asymmetry is deliberate: `warn` proceeds to inference, `reject` does not, so the hard floor
    sits at half the soft floor rather than at it.

    Raise `ValueError` on undecodable bytes; never let a `PIL.UnidentifiedImageError` escape.

    Guard the decode itself: before opening, if `len(data)` exceeds a caller-supplied ceiling, the
    caller is responsible for refusing — expose that as `MAX_DECODE_PIXELS` protection instead by
    setting `PIL.Image.MAX_IMAGE_PIXELS` to 50_000_000 at module import so a decompression-bomb
    image raises rather than exhausting the VPS's memory.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram-downloaded bytes → Pillow decoder | Fully attacker-controlled binary reaches a native image parser here |
| Image bytes → base64 data URL → OpenRouter | The same bytes leave the VPS to six third parties |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of service | `grade_image` decoding a decompression bomb | mitigate | `PIL.Image.MAX_IMAGE_PIXELS = 50_000_000` set at module import, so a crafted small file that expands to gigapixels raises instead of exhausting the VPS. Acceptance criterion greps for it. |
| T-03-02 | Denial of service | Unbounded download of a hostile document | mitigate | `MAX_IMAGE_BYTES` (default 10 MiB) is checked by the caller in plan 06 before `grade_image` is reached; this module never decodes a payload it was not handed. |
| T-03-03 | Information disclosure | Image bytes or their base64 form reaching logs | mitigate | This module contains no logging calls at all. `to_data_url` returns a value; it never logs one. Nothing here writes to stdout. |
| T-03-04 | Tampering | SSRF via a URL supplied instead of an image | mitigate | `to_data_url` accepts `bytes` only and inlines them as a base64 data URL. No code path in this phase ever hands OpenRouter an `http(s)://` image URL, and no user-supplied string is ever fetched. |
| T-03-05 | Elevation of privilege | Native-code CVE in Pillow's decoders | accept | Pillow is pinned at 12.3.0, the current release; the container runs non-root with no mounted host filesystem. Upgrading on advisory is the standing response. |
</threat_model>
