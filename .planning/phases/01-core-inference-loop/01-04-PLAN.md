<objective>
Turn six independent verdicts into one honest sentence. Implement the tally — vote counts, tier boundaries, lab spread inside the majority, abstention degradation, and the minimum-voter floor — and the reply rendering that puts reasoning first and the letter last inside a spoiler, or shows no letter at all when the models did not converge.

This is where the project's core value is either honored or quietly broken. Every string produced here is a copy-discipline decision: agreement means the models converged, never that the answer is correct.

Purpose: make the confidence signal match the evidence, including when the evidence is weak.
Output: `orchestrator/consensus.py` (pure, no I/O) and the finished `formatting/reply.py`.
</objective>

  <action>
    Write `src/bot/orchestrator/consensus.py` as a pure module — no imports from `aiogram`,
    `httpx`, or `bot.config`, and no I/O other than a single `logging.getLogger(__name__)`.

    `MIN_VALID_RESPONSES_DEFAULT = 3`.

    `tally(results, *, min_valid=MIN_VALID_RESPONSES_DEFAULT) -> ConsensusResult`:
    1. Split `results` into `ok` and `abstain` by `status`. `abstentions = len(abstain)`,
       `total_valid = len(ok)`, `degraded = abstentions >= 2` (INF-14).
    2. If `total_valid < min_valid`, return `ConsensusResult` with tier `insufficient`,
       `winning_letter=None`, `positions=[]`, and the counts filled in. Return before any
       vote maths — a consensus drawn from two voters is not a consensus.
    3. Count votes over `r.verdict.answer` for `ok` results, skipping any whose `answer` is `None`.
    4. Build one `Position` per distinct letter: `votes`, `labs` (distinct `r.lab` among that
       letter's voters), and `reasoning` = the `reason` string of the `ChoiceVerdict` whose
       `verdict == "selected"` for each voter, deduplicated case-insensitively while preserving
       first-seen order. Sort `positions` by `votes` descending, then by `letter` ascending for
       determinism.
    5. Tier: `strong` when `positions[0].votes / total_valid >= 5/6` OR the split is exactly
       `total_valid` to 0; `contested` when `positions[0].votes > total_valid / 2` and not
       `strong`; `unresolved` otherwise. When the top two positions have equal votes, force
       `unresolved` regardless of ratio.
       Concretely for six voters: 6/0 and 5/1 are `strong`, 4/2 is `contested`, 3/3 and anything
       flatter is `unresolved` (CON-03, CON-04, CON-05).
    6. `winning_letter` is `positions[0].letter` for `strong` and `contested`, and `None` for
       `unresolved` and `insufficient` — showing a plurality letter on an unresolved split would
       imply a confidence the models do not have.
    7. `labs_in_majority = positions[0].labs` when a winner exists, else the count of distinct labs
       among all `ok` results (CON-02).
    8. `transcription_divergence`: normalize each `ok` result's `passage_transcription` by
       lowercasing, stripping punctuation, and splitting on whitespace; for every pair of `ok`
       results whose `lab` values differ, compute Jaccard token overlap; set True if any such pair
       scores below 0.9. Log one WARNING naming the two model IDs and the score when True. This is
       passive instrumentation for the deferred eval harness (PROJECT.md "Silent failure modes") —
       it is computed and logged in this phase and is not yet surfaced in the reply.
    9. `question_type`: the modal non-`None` `verdict.question_type` among `ok` results; `None` on
       a tie.

    Write `tests/test_consensus.py` covering every behavior above with hand-built `AttemptResult`
    lists. Add a helper `make_ok(model_id, lab, answer, reason=..., transcription=...)` at the top
    of the test module rather than repeating construction.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model-generated text → Telegram message | Six independent untrusted text sources are interpolated into one outbound message |
| Model-generated transcription → WARNING log line | Passage text, itself derived from a user image, reaches the log sink |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Denial of service | Unescaped model punctuation causing a 400 `can't parse entities`, so the user gets nothing | mitigate | All output is built from `Text`/`Bold`/`Spoiler` entity objects rather than interpolated MarkdownV2 strings; a dedicated adversarial-character test asserts reserved characters survive verbatim. |
| T-04-02 | Tampering | Model output containing markup that impersonates bot chrome (a fake header line, a fake spoiler) | mitigate | Model text only ever occupies `Position.reasoning` body lines prefixed with `• `; the header and the spoiler letter are constructed from typed `ConsensusResult` fields, never from model prose. |
| T-04-03 | Information disclosure | Full passage transcriptions written to logs by the divergence check | mitigate | The divergence WARNING logs the two model IDs and the numeric overlap score only — never the transcription text itself. |
| T-04-04 | Repudiation | A reply implying the bot verified correctness | mitigate | Four forbidden phrases are asserted absent from the module source by an acceptance criterion and by a unit test; unresolved rounds carry no letter at all. |
| T-04-05 | Information disclosure | Reasoning lines echoing text a user embedded in an image to exfiltrate prompt content | accept | Reasoning is capped at four lines for `strong` and is scoped to elimination rationale; the shared prompt contains no secrets, so echoed content has no confidentiality value. |
