  <action>
    Rewrite `src/bot/pipeline.py`. Delete `_STUB_CONSENSUS` and every reference to it.

    Define `Deps` as a frozen dataclass holding `settings: Settings`, `roster: RosterConfig`,
    and `http: httpx.AsyncClient` — one shared client for the process, so six concurrent calls
    reuse the connection pool instead of paying six TLS handshakes per question.

    `async def answer_question(deps: Deps, image_bytes: bytes, *, source_is_photo: bool) -> Text`
    executes strictly in this order and returns at the first branch that fires:
    1. If `not image_bytes` or `len(image_bytes) > deps.settings.max_image_bytes`, log one WARNING
       with the byte length and return `build_rejection(RejectionReason.unreadable_image, source_is_photo=source_is_photo)`.
       This check precedes decoding so a hostile payload is never handed to Pillow.
    2. `report = grade_image(image_bytes, min_dimension=deps.settings.min_image_dimension,
       blur_warn=deps.settings.blur_variance_warn, blur_reject=deps.settings.blur_variance_reject)`,
       catching `ValueError` and returning the same `unreadable_image` rejection.
       If `report.grade is QualityGrade.reject`, return that rejection — before any inference spend
       (ING-05). If `report.grade is QualityGrade.warn`, log one WARNING naming
       `report.reason`, `report.width`, `report.height`, and `report.blur_variance`, and proceed.
    3. `data_url = to_data_url(image_bytes)`.
    4. `results = await run_round(deps.http, deps.roster, data_url,
       base_url=deps.settings.openrouter_base_url, api_key=deps.settings.openrouter_api_key,
       per_model_timeout=deps.settings.per_model_timeout_seconds,
       round_timeout=deps.settings.round_timeout_seconds)`.
    5. Let `voters = [r for r in results if r.status == "ok" and r.verdict is not None]`.
       If `voters` is non-empty and a strict majority of `voters` have `verdict.is_sat_verbal is False`,
       return `build_rejection(RejectionReason.not_sat_verbal, ...)` (ING-06).
       Then, if a strict majority of `voters` have `verdict.question_count > 1`, return
       `build_rejection(RejectionReason.multiple_questions, ...)` (ING-07).
       Both decisions are taken over returning models only — that is CONTEXT.md's explicit choice
       to avoid a seventh classifier call, which would add a whole round-trip against the primary
       latency risk. When `voters` is empty, skip both checks and fall through to step 6, where the
       `insufficient` tier produces the apology.
    6. `consensus = tally(results, min_valid=deps.settings.min_valid_responses)` and return
       `build_reply(consensus, source_is_photo=source_is_photo)`.
    Log one INFO line at the end of a completed round: tier, winning letter presence as a bool
    (never the letter itself), total_valid, abstentions, and elapsed wall clock.

    Write `tests/test_pipeline.py` covering every behavior above. Construct `Deps` with a
    `Settings` built from `monkeypatch.setenv` values and an `httpx.AsyncClient` bound to an
    `httpx.MockTransport` whose handler branches on the request body's `model` field, so each of the
    six models can be scripted independently. Reuse the image helpers from `tests/test_images.py`
    by importing them, and the verdict builders from `tests/fixtures/verdicts.py`.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram update → handler | Attacker-controlled bytes, MIME type, and file name arrive here |
| Handler → pipeline | The byte ceiling and the quality gate are the only things between a payload and six paid API calls |
| Model `is_sat_verbal` / `question_count` fields → control flow | Model output, itself influenced by image content, decides whether a rejection is sent |
| Reply send → Telegram | A malformed entity structure here means the user gets nothing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Denial of service | Unbounded image download driving memory and inference spend | mitigate | `len(image_bytes) > settings.max_image_bytes` (default 10 MiB) is checked as step 1, before decoding and before any HTTP request. A test asserts zero requests reach the transport on that branch. |
| T-06-02 | Denial of service | A user resending the same unreadable photo repeatedly | mitigate | The quality gate rejects before the round, so a hostile or hopeless image costs zero inference. Per-user rate limiting is ACC-03, scoped to Phase 2. |
| T-06-03 | Tampering | Image-embedded text steering `is_sat_verbal` or `question_count` to force a rejection | accept | The worst outcome is the attacker's own request being refused; the decision requires a strict majority of returning models, so a single manipulated model cannot flip it. |
| T-06-04 | Information disclosure | `file_name`, image bytes, or the data URL reaching logs | mitigate | Handler logging is restricted to `chat.id` and byte length; an acceptance criterion greps for the absence of `file_name`. The pipeline logs the tier and counts but never the winning letter or the transcription. |
| T-06-05 | Denial of service | A `TelegramBadRequest` on send dropping the reply entirely | mitigate | The send is wrapped in a `try/except TelegramBadRequest` that re-sends the plain text with no entities, so an answer that cost real money always reaches the user. |
| T-06-06 | Spoofing | Any Telegram user reaching the pipeline and spending budget | accept | Allowlist (ACC-01) and per-user caps (ACC-03) are Phase 2. Phase 1 runs against an unpublished bot handle. |
| T-06-07 | Elevation of privilege | A non-image document reaching Pillow or OpenRouter | mitigate | `select_file_id` returns `None` for any document whose `mime_type` does not start with `image/`, and the handler replies with `no_image` rather than downloading it. |
</threat_model>
