## Phase Goal

Every question and model attempt is durably recorded, duplicate images short-circuit to a cached answer with no new spend, and the bot stays within its budget and its allowlist as real usage accrues.

This plan delivers the slice: **a student who re-sends a question they already asked — or asks a question a classmate already asked — gets the answer back instantly and it costs the owner nothing.**

<objective>
Compute a 256-bit perceptual hash of every submitted image and short-circuit the entire inference round on an exact hash match, serving the stored consensus instead.

Purpose: at $0.11 per question measured live, the cache is the single largest margin lever in the product. Students work through the same official practice sets, so exact re-sends of the same image are the common case, not the exception. Every hit is a question served at zero marginal cost.

Output: `compute_phash`, an exact-match lookup, a cache branch at the top of `answer_question`, and a persisted `served_from_cache` audit row.
</objective>

<locked_decision>
**Exact perceptual-hash matching only, at `hash_size=16`. No Hamming-distance threshold, no fuzzy matching, in this phase or any part of v1.**

This is not a tuning parameter left to the executor. `.planning/research/PITFALLS.md` establishes that SAT Reading & Writing questions from the same test form share almost everything visually — same font, same passage box, same four-choice layout — and that DCT-based perceptual hashing deliberately discards exactly the fine detail (the words) that distinguishes two different questions. A fuzzy match in this domain does not produce a visible error; it produces a normal-looking, fully confident cached answer for the *wrong question*, which is precisely the failure the entire product exists to prevent. Exact equality is structurally incapable of that failure for any two images that hash differently.

`hash_size=16` yields a 256-bit hash rather than the library's 64-bit default, retaining far more content signal under the near-constant template. `.planning/research/ARCHITECTURE.md` reaches the same conclusion independently: ship exact-phash-match caching first, defer fuzzy matching entirely.
</locked_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram user → phash | Image bytes are attacker-controlled and are decoded by Pillow before hashing |
| Cache row → reply | A stored `consensus_json` is replayed to a *different* user than the one who paid for it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Spoofing | `find_cached_question` | mitigate | Exact 256-bit hash equality only. No Hamming threshold exists in the code path, so a near-miss image cannot impersonate a stored question. Enforced by the grep acceptance criterion in Task 1. |
| T-02-09 | Tampering | cached answer integrity | mitigate | `image_sha256` is compared on every hit and a mismatch is logged with both question ids, giving a queryable collision signal without changing the matching rule. |
| T-02-10 | Denial of service | Pillow decode of hostile images | mitigate | `Image.MAX_IMAGE_PIXELS = 50_000_000` is already set at `extract.py` import and the existing `max_image_bytes` ceiling in `pipeline.py` runs before any decode. `compute_phash` adds no new decode path outside those guards. |
| T-02-11 | Information disclosure | cross-user cache serving | accept | All allowlisted users are paying customers of the same study product and the cached artifact is a model consensus over a public practice question, not user data. The cache is intentionally global, which is what makes it a margin lever. |
| T-02-12 | Denial of service | cache lookup failure | mitigate | Lookup is wrapped in `try/except`; failure falls through to a normal paid round rather than an error reply. |
| T-02-SC | Tampering | `pip install imagehash` | mitigate | `imagehash==4.3.2` is a locked-stack package in PROJECT.md, verified live against the PyPI JSON API in `.planning/research/STACK.md` on 2026-09-10. Status `[VERIFIED]`; the pinned version must not be floated. |
</threat_model>
